# Server Control MCP

[![tests](https://github.com/Gengetau/server-control-mcp/actions/workflows/ci.yml/badge.svg)](https://github.com/Gengetau/server-control-mcp/actions/workflows/ci.yml)
[![License: Apache-2.0](https://img.shields.io/badge/License-Apache--2.0-blue.svg)](LICENSE)

A self-hosted Linux server-control integration: remote MCP clients call file, patch,
command, terminal-session, Git and image tools through persistent OAuth, and can
optionally subscribe to directed events.

**Status: 0.1.0, first extracted release.** Target platform Linux / Python 3.11+.
The execution core is [coding-tools-mcp](https://github.com/xyTom/coding-tools-mcp)
`0.3.0`, installed unchanged; this project adds a persistent OAuth gateway, an event
adapter and deployment integration. It is not an official upstream release and not an
independent execution engine.

[中文](README.md) · [Deployment](docs/deployment.md) · [Events](docs/events.md)
· [Security](SECURITY.md) · [Provenance](docs/provenance.md)

> [!WARNING]
> This service lets authenticated clients **run commands and read/write files on the host**.
> Single operator only. Publish only the OAuth gateway through a rate-limited HTTPS
> ingress; never expose the executor port; never run it as root.
> Read [SECURITY.md](SECURITY.md) before deploying.

## Requirements

- Linux, Python 3.11+ (CI covers 3.11 / 3.12 / 3.13)
- Your own HTTPS reverse proxy or tunnel (this service does not issue TLS certificates)
- Optional: Docker Compose (Linux host networking) or systemd

## What it provides

| Feature | Source |
|---|---|
| 18 default file, command, Git, image and environment tools | upstream coding-tools-mcp |
| Base MCP, OAuth/PKCE, dynamic client registration | upstream |
| SQLite persistence of registrations, auth codes, refresh grants | this project |
| Refresh rotation, replay revocation, revocation endpoint | this project |
| Directed events, persistent subscriptions, signed callbacks with retry | this project, experimental, off by default |
| Two-process supervisor, authenticated backend, systemd / Docker examples | this project |

### Tools (18, upstream)

| Category | Tools |
|---|---|
| Environment | `server_info`, `check_exec_environment`, `request_permissions` |
| Files | `read_file`, `list_dir`, `list_files`, `search_text`, `apply_patch` |
| Commands / terminal | `exec_command`, `write_stdin`, `read_output`, `kill_command` |
| Git | `git_status`, `git_diff`, `git_log`, `git_show`, `git_blame` |
| Images | `view_image` |

With events enabled the gateway also serves `server/discover` and `events/*`.

OAuth only authenticates callers; all authorized clients share one OS account and
workspace. Intended for clients you control, not for mutually untrusted tenants.

## Quick start

Run from the project root as an ordinary user:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/server-control-mcp init
mkdir -p workspace
```

Edit the generated `.env`: set `CODING_TOOLS_MCP_SERVER_URL` to your **HTTPS origin**,
e.g. `https://mcp.example.com`, without `/mcp`; adjust `SCM_WORKSPACE` as needed. Keep the
generated password and signing key, and keep `.env` outside the workspace. The file is
literal `KEY=value`; no quotes or shell expressions.

```bash
.venv/bin/server-control-mcp --env-file .env serve
```

The executor listens on `127.0.0.1:28766` (protected by a per-start internal Bearer token)
and the OAuth gateway on `127.0.0.1:28767`. Expose only the **gateway** through your own
HTTPS reverse proxy or tunnel. See [deployment](docs/deployment.md).

In a client that supports remote MCP OAuth, add:

```text
https://mcp.example.com/mcp
```

Sign in with the generated operator password. Clients supporting dynamic registration
normally need no pre-filled Client ID / Secret. Token refresh and experimental Events
support depend on the client; this release has not been re-validated per platform.

## Configuration

Keys written by `init` (full reference in [deployment](docs/deployment.md)):

| Key | Meaning |
|---|---|
| `CODING_TOOLS_MCP_SERVER_URL` | required HTTPS origin, no path |
| `CODING_TOOLS_MCP_OAUTH_PASSWORD` / `..._TOKEN_SECRET` | generated by init, at least 32 chars |
| `CODING_TOOLS_MCP_OAUTH_TOKEN_TTL` | access token lifetime, default 3600 s |
| `SCM_STATE_DIR` / `SCM_WORKSPACE` | private state dir / executor workspace (must not nest) |
| `SCM_BACKEND_PORT` / `SCM_GATEWAY_PORT` | 28766 / 28767, bound to 127.0.0.1 only |
| `SCM_PERMISSION_MODE` | `safe` (default) / `trusted` / `dangerous` |
| `SCM_EVENTS_ENABLED` | `0` (default) / `1` |

## Permission modes

Enforced by upstream coding-tools-mcp 0.3.0:

| Mode | Network commands | Shell expansion / inline scripts | Landlock (if kernel supports) | Secret env filtering | Global /tmp writes | Skip all permission checks |
|---|---|---|---|---|---|---|
| `safe` (default) | no | no | yes | yes | blocked | no |
| `trusted` | yes | yes | yes | yes | prefixed only | no |
| `dangerous` | yes | yes | no | no | allowed | **yes** |

`dangerous` amounts to unrestricted execution as the service account; use only in an
isolated environment. Check `server_info` / `check_exec_environment` for what is actually enforced.

## Optional events

Set `SCM_EVENTS_ENABLED=1` and restart; clients supporting experimental MCP Events can
subscribe to `server.changed`. A local producer targets an exact OAuth `client_id`:

```bash
.venv/bin/server-control-mcp --env-file .env emit \
  --recipient YOUR_OAUTH_CLIENT_ID --kind task.assigned
```

Callbacks carry only event id, kind and time; no task body, and delivery does not mean the
task was handled. See the [event contract](docs/events.md).

## Docker and systemd

- Linux Docker: generate `.env` on the host (compose overrides its state/workspace paths with named volumes):

  ```bash
  python3 -m venv .venv && .venv/bin/python -m pip install .
  .venv/bin/server-control-mcp init          # creates .env
  # edit CODING_TOOLS_MCP_SERVER_URL in .env
  docker compose up -d --build
  ```

  The example uses an unprivileged container user (UID 10001), named volumes and Linux host
  networking; you still configure HTTPS ingress yourself.
- Long-running: adapt the [systemd template](deploy/server-control-mcp.service).
- No dependency on any particular cloud vendor, personal tokens or personal domains.

## Testing and packaging

```bash
python -m pip install -e .
python -m unittest discover -s tests -v
python scripts/smoke.py
python scripts/release.py --check-only
python scripts/release.py
```

The smoke test starts the real executor and gateway on random loopback ports in a temporary
directory and exercises OAuth login, file and command calls, restart persistence, refresh
and revocation; it never touches a production server or public port. The release script
builds an allowlisted source ZIP and rejects common credential patterns, plus any extra
regexes listed in an untracked local `.release-denylist` file. See [VALIDATION.md](docs/VALIDATION.md).
